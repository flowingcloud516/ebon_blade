# Ebon Blade UI设计

> **文档定位**：应用与UI模块设计。
>
> **主要作用**：定义工作空间、页面结构、交互边界和后台执行关系。
>
> **使用方式**：修改`src/ebon_blade/`中的界面、工作空间或运行桥接前阅读。

层级：模块设计

最后复核：2026-10-30

## 1. 职责

UI负责工作空间选择、测试类型显示、环境组合编辑、环境档案管理、初始化任务启动、进度展示和停止请求。UI不直接执行SSH、串口、BMC或具体环境命令。

## 2. 工作空间

用户选择一个本地目录作为工作空间。工作空间保存：

- 本机设置；
- 测试类型显示名称；
- 环境档案；
- 本次环境组合；
- 运行快照、日志和结果。
- Linux版本仓连接配置：IP、端口、用户名、密码和`base_repo_dir`。

环境档案与本次组合分离，同一个档案可以跨任务复用。保存使用原子替换和内容摘要，避免多个窗口静默覆盖。

版本仓配置位于工作空间卡片中：首页只显示`IP:port`与`base_repo_dir`，点击“版本仓配置”进入二级弹窗维护用户名和密码。第一期按用户确认允许密码明文保存在`workspace.json`，但首页、运行快照和普通日志不得显示密码。

## 3. 页面结构

第一版主界面分为：

1. 左侧测试类型导航和显示名称编辑；
2. 工作空间选择及版本仓摘要/二级配置；
3. 本次环境组合；
4. Benchmark方案预留区；
5. 环境初始化、离线演示、停止请求和结果展示。

![当前客户端预览](images/client-preview.png)

布局参考：[原始布局图](images/client-layout-reference.png) · [批注意见](images/client-layout-feedback-v2.png)

所有项目内二级弹窗以及组合框下拉列表使用固定的浅色背景与深色文字，不继承Windows系统的深色窗口配色，避免外层背景、标题、选项文字和白色表单区域形成不可读的明暗冲突。下拉列表选中项统一使用浅绿色背景和深色文字。

## 4. 运行边界

初始化必须在后台线程执行，界面线程只接收进度和结果。离线演示不得连接设备，也不得报告真实Ready。真实执行应通过产品运行层调用`EnvironmentControlService`，而不是在按钮回调中直接访问Connector。

## 5. 当前待接通

现有GUI仍保留早期Adapter运行边界。后续需要把真实环境初始化桥接到`EnvironmentControlService`和`EnvironmentDriver`，并保持当前工作空间、锁和结果文件兼容。
