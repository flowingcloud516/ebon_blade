# EVB Environment Model 实施计划

状态：等待设计与耗时评审，不进入实现

最近更新：2026-10-27

本计划只描述实现顺序、交付物和验证点。真实芯片名称、命令、文件名、成功标志和环境操作留在内部实现。

## 1. 实施原则

- 先打通目录、配置和Fake Adapter，再接真实启动源码。
- 每个Phase/Step都通过现有`PlanExecutor`执行，不另写一套EVB主循环。
- 高耗时动作必须有进度、成功/失败证据、总超时和取消语义。
- FileZilla清空是破坏性操作，必须先完成路径安全和独占锁实现。
- 5路串口日志必须早于任何设备操作启动，并持续到用户结束本次运行。
- 设计评审通过前不修改真实设备。

## 2. 工作包与顺序

### P1：补齐工作空间和界面字段

1. 给每个EVB `TargetSelection`增加可见的`platform/version`选择，不放进环境档案。
2. 同一组合的多个EVB可以选择不同版本；相同版本共享备料结果。
3. EVB环境档案增加PN码、BMC网络、EVB-GE目标网络、5个串口和EVB SSH凭据。
4. 本机设置增加Linux版本机与FileZilla根目录/账号配置。
5. 明文保存字段仍要在日志与诊断快照中脱敏。

验证：保存、关闭、重新打开后字段恢复；不同工作空间不互相读取版本和凭据。

### P2：实现最小版本目录服务

1. 实现`SimpleVersionStore.list_platforms()`、`list_versions()`和`ensure_local()`。
2. 补足SSH/SFTP递归列目录和递归下载能力；当前SSH Connector的`download()`只支持单文件，不能假装已经支持目录。
3. 下载先进入`.downloading`目录，成功后原子改名。
4. 增加Run级`platform + version`去重；相同版本第二次返回复用结果。
5. 不增加Manifest、SHA-256或数据库。

验证：缓存命中不连接服务器；中断不产生最终目录；两个EVB同版本只下载一次。

### P3：实现安全的本地准备服务

拆出`EvbWorkspaceMaterializer`与`FileZillaRootLease`：

1. 解析并验证所有绝对路径。
2. 对FileZilla根目录建立跨任务/跨进程独占锁。
3. 拒绝危险根目录、工作空间及其父目录，并使用所有权标记。
4. 只清空FileZilla根目录；绝不递归清空工作空间。
5. 安全解压固件，拒绝越界路径和链接。
6. 按内部适配层允许列表准备启动脚本、驱动和三方包。
7. 对工作空间内已存在的适配层目标使用临时路径和替换，不接触未知文件。

验证：错误配置不能删除盘符根目录、工作空间或任意用户目录；失败后没有半份正式目标。

### P4：定义并Fake实现启动适配层

1. 定义`EvbRunRequest`、`EvbArtifactBundle`、`EvbActionDefinition`、`EvbActionContext`和`EvbStartupAdapter`。
2. Adapter分别声明`configure/start/operate`动作，不能返回一整个黑盒初始化函数。
3. 为每个动作定义超时、SideEffect、成功/失败证据和取消策略。
4. 实现Fake Adapter，覆盖立即成功、等待后成功、明确失败、超时、取消和未知状态。
5. 在内部建立真实芯片/版本到Adapter的注册映射。

验证：Plan在执行前结构固定；内部Action逐项成为普通Step；工作空间不能加载任意Adapter代码。

### P5：补齐必需日志生命周期

1. 实现5个`SharedSerialLogCollector`，每个使用独立`OBSERVE_ONLY`会话和独立原始日志。
2. 增加必需Collector启动失败的阻断语义；当前`LogSession.start_errors`只记录错误，不足以满足EVB要求。
3. 实现内部`DeferredEvbSshLogCollector`：初始化前启动等待任务，但只在Phase 2成功、EVB IP生效后尝试连接。
4. BMC SSH不创建持续Collector。
5. `finish_run()`统一停止Collector并关闭连接。

验证：串口Collector早于Phase 0；初始化失败后仍继续采集；结束运行后全部关闭；任一路必需串口日志无法启动时不操作设备。

### P6：实现四Phase `EvbModel`

1. `definition()`与`validate_config()`。
2. Phase 0：版本解析、去重下载、四类制品检查。
3. Phase 1：FileZilla Lease、安全清空、固件解压、工作空间准备、启动配置渲染。
4. Phase 2：把Adapter启动动作转换为Step，等待明确成功，管理FileZilla Lease释放。
5. Phase 3：SSH就绪、持续日志接入、两个SFTP上传和内部环境动作。
6. `verify_ready()`与只读失败上下文。

验证：顺序固定；启动成功前绝不连接EVB SSH；失败后不执行后续Phase；每个Step结果包含耗时和证据。

### P7：接入客户端后台执行

1. 将当前GUI使用的旧同步Adapter入口桥接到`EnvironmentControlService`。
2. 把Phase/Step进度映射到当前进度区和运行日志。
3. 多个EVB严格顺序初始化，避免FileZilla根目录和工作空间准备文件互相覆盖。
4. 相同版本显示“复用已备料版本”，而不是再次下载。
5. 停止按钮只取消后续调度和可安全取消的本地动作，不把未知设备动作显示成已取消成功。

验证：窗口在长下载、解压、启动和上传期间保持响应；关闭/重新打开工作空间不会伪造Ready。

### P8：内网适配与真实验证

1. 内部补齐真实串口角色、文件名和参数模板。
2. 把启动源码接入`EvbStartupAdapter`，逐项配置成功/失败标志和实际超时。
3. 补齐驱动、三方包上传目标和环境上操作。
4. 补齐最终只读就绪检查。
5. 按真实耗时回填设计表，不沿用未经验证的默认超时。

验证：正常流程、缓存命中/缺失、启动失败、串口断连、SSH超时、上传中断、用户取消和最终检查失败均有明确结果。

## 3. 关键UT

### 公共仓库可完成

- 四个Phase及Step顺序、ID、SideEffect和失败传播。
- 相同版本多EVB只备料一次，不同版本分别准备。
- 缺少任一制品时在设备动作前失败。
- 危险FileZilla路径全部拒绝。
- ZIP路径穿越、绝对路径和链接项拒绝。
- 只清理适配层拥有的工作空间目标，不删除`workspace.json`、`versions/`或`runs/`。
- 启动失败/未知时不创建EVB SSH连接，不上传包。
- 上传驱动成功后第三方包失败，后续内部操作不执行。
- 必需串口Collector启动失败时不进入Phase 0。
- 初始化失败后LogSession仍存活，`finish_run()`后关闭。
- 取消下载/解压可清理临时文件；取消启动不自动重放动作。
- `verify_ready()`失败时Plan虽完成但环境不标记Ready。

### 内网必须完成

- 5路共享串口同时连接启动脚本和日志Collector。
- 真实版本目录与四类文件映射。
- FileZilla清空、解压和设备取固件的完整周期。
- 每个真实启动Step的成功、失败、超时和历史日志隔离。
- EVB-GE地址生效后SSH登录、持续日志和SFTP上传。
- 驱动、三方包与内部环境操作。
- 最终Ready条件。

## 4. 第一轮耗时验证记录模板

内网执行时为每个高耗时Step记录：

| 字段 | 内容 |
| --- | --- |
| Step ID | 例如`2.3 startup.flash` |
| 正常最短/典型/最长 | 三个真实观测值 |
| 建议总超时 | 应大于正常最长值并留合理余量 |
| 无输出最长时间 | 用于判断是否需要idle timeout |
| 成功/失败标志 | 具体证据，不能只写“脚本返回” |
| 超时后设备状态 | 已停止 / 仍在运行 / 未知 |
| 可否安全取消 | 是/否及内部方法 |
| 可否安全重试 | 默认否；若是需说明幂等依据 |

完成真实测量前，设计文档中的5分钟、10分钟、60分钟等数值只作为防止无限等待的保守初值；文件类动作已经根据“不超过5GB”收紧，内部设备动作仍等待实测。

## 5. 实施完成判定

只有以下条件全部满足，才算EVB第一期实现完成：

1. 用户能在主界面为每个EVB选择版本并保存配置。
2. 同版本备料被复用，目录准备符合三层目录约定。
3. 5路串口日志贯穿初始化到结束运行。
4. 四Phase逐Step执行并显示真实结果。
5. 启动后才能连接EVB SSH并上传两个包。
6. 内部环境操作和最终Ready检查真实通过。
7. 任一失败、超时、取消或未知状态都不会被显示为环境准备成功。
